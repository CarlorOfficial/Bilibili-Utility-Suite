# B站综合插件发行说明规范

后续 Gitee 发行版统一使用本目录中的 Markdown 结构。发行说明应直接描述用户可感知的变化，避免按 Windows、Linux 重复罗列完全相同的内容。

## 标准模板

```markdown
# B站综合插件 X.Y.Z 更新日志

发布日期：YYYY-MM-DD

本次更新主要……

## 功能主题

- 具体变化一。
- 具体变化二。

## 升级须知

- 当前插件版本为 `X.Y.Z`。
- Windows 与 Linux 用户分别下载对应平台的完整发布包。
```

## 编写规则

- 一级标题固定为“B站综合插件 + 版本号 + 更新日志”。
- 标题下方固定写发布日期，再用一段话概括本次更新重点。
- 按功能主题使用二级标题，不在每一条前重复“新增”“修复”“优化”等方括号标签。
- Windows 与 Linux 内容相同时合并描述；确有差异时再使用三级标题区分平台。
- 公开发行说明只写用户可感知的新增、修复、优化和升级须知。
- 自动测试、签名、外发包审计、文件哈希与其他内部验证仍需在发布前完成，但不写入 Gitee 更新日志。
- 不写未实现功能，不把推测写成已完成事项，不在发行说明中暴露令牌、私钥或其他敏感信息。
